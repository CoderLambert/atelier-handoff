# UI 组件设计与验收

## 设计基准

目标为中、大屏 PC 桌面工作台。以 1280×800 和 1440×900 检查主路径，宽屏用 1920×1080 检查内容是否过散。手机布局按明确的移动端需求另行安排。先阅读项目内 [shadcn 官方 Skill](../skills/shadcn/SKILL.md)，以 `frontend/components.json` 的 new-york、TypeScript、CSS variables、Lucide 和现有组件目录为准。新增控件先查官方组件及 variants，再判断是否需要特制原生交互。

## 组件放在哪里

| 范围 | 所有者与接口 |
|---|---|
| `components/ui/` | 基础控件。沿用 shadcn、Radix、已有 `Button` 和 `Dialog`。以 `variant`、`size`、`disabled`、`aria-*` 等标准 props 表达状态。保持对业务、路由、Redux、API 和 Electron 的独立。 |
| `components/` | 跨功能组合。已有消费者的文件预览等在此维护。通过类型化 props、slots 和动作回调复用。可控值与初始值二选一。 |
| `features/<领域>/` | 业务组件。接收展示数据和 `onOpen`、`onRemove`、`onApprove` 等语义动作。多步交互由同域的 `hooks/use-<用例>.ts` 管，网络操作由 `use-query/<领域>/` 提供。 |
| `app/` | 页面、窗口及工作区组合。负责布局、导航与焦点归还，通过业务 hook 连接数据。 |

设计新组件时先查现有封装及实际使用点。把业务语义变化的部分留作 props 或 children。多个互斥布尔值用联合类型或单一 `variant` 表达。公共组件保持稳定的可访问名称和事件语义。

## 视觉、排版与内容

- 使用项目的字体、字号、间距、表面、边框和颜色 token。保留已确认的工作台风格。确实需要新 token 时从多个使用场景核对命名、对比度和状态。
- 一个任务区优先一个主操作，其余按用途放到同一工具栏。文案只承载识别、操作、状态或恢复信息。状态使用文字或图标配合颜色。正文、代码和背景的对比度按普通文字至少 4.5:1 验收。
- 表单字段有可见 label、明确单位与错误关联；同一行的控件顶端对齐。列表项展示可识别名称、目标及必要状态。编辑器多条记录采用列表选择再编辑，草稿随记录保留。
- 以内容决定布局。主工作区随窗口扩展，正文设置舒适行宽，数据列表、代码和预览使用可用宽度。关联的列表与编辑面板可并列。用一层明确的标题、分组和主操作组织页面，避免卡片套卡片和重复提示。长文件名、URL、连续代码和表格在所属区域换行、截断或横向滚动；截断内容提供查看全文的方式。

## 交互组件的约定

- 弹窗组合 `DialogContent`、`DialogTitle`、`DialogDescription`、正文与操作区，优先使用现有触发/关闭组件。长内容在正文滚动，保存、取消和关闭可达。验证初始焦点、Tab 顺序、Esc、关闭后焦点返回；未保存和提交中行为要明确。
- 点击附件名称打开预览，移除通过独立按钮。图标按钮使用 `type="button"` 和 `aria-label`。输入框保留 IME、粘贴和键盘提交；异步过程中防止重复提交并保全输入。
- 每个有远端数据的视图可演示加载、成功、空、失败重试及禁用状态。查询层拥有请求状态；组件从 hook 接收 `isPending`、错误、数据与重试动作。用 effect 同步两个状态副本前，先判断能否直接派生值。
- Electron 的原生网页层由宿主挂载。弹窗覆盖、窗口缩放、标签切换和隐藏时同步 BrowserSlot。需要人手接管的网站必须能实际输入和滚动。

## 合入标准

走一遍核心用户操作，在中屏和大屏 PC 检查主次操作、阅读行宽、留白、内容滚动和键盘焦点；涉及桌面原生层时再从真实 Electron 窗口验证。设计结果以用户可观察的行为和截图说明；若引用校验数值，记录实测条件。
