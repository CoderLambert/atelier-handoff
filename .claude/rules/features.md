# 功能模块

- 一个 feature 围绕一个用户操作组织。入口公开组件、服务或稳定类型；其他模块通过公开接口使用它。依赖方向从 UI 到用例、从适配器到契约；共享纯逻辑放在实际复用的最窄层级。
- 新接一种 Skill、MCP 或桌面能力，先检查项目已有 provider、授权和审批契约。配置能表达的行为走现有注册/解析链路。新增执行器需说明真实执行端、失败反馈与权限收回时间点。
- 文件、附件和交付物以项目/会话身份与不可变内容标识关联。导入与运行分别校验；UI 显示的可用性必须与服务端一致。
- 实施前列出要保留的可见行为和回退路径。改动后用实际入口走完用户流程，并覆盖一个可能的失败或撤销场景。独立包改动还需验证真实安装产物、导出类型和资源加载。
