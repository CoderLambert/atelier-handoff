# atelier. · 本机 AI 工作台

atelier 是一个面向个人项目的桌面 AI 工作台。在同一个窗口中绑定本地项目，与 AI 协作处理文件、命令和网页，并查看执行过程、审批记录与生成的成果。

- **对话与执行**：流式对话、工具调用明细、子任务进度、停止与会话恢复。
- **项目与文件**：浏览项目文件、引用上下文、上传文本附件，以及预览和导出成果。
- **浏览器协作**：使用内置网页面板，按项目授权 Agent 操作，并可随时人工接管。
- **权限与扩展**：按会话选择运行模式，管理项目智能体、Skills 和 MCP 工具。
- **本地数据**：项目、会话与运行记录保存在本机，桌面版支持数据迁入和备份。

应用使用 Electron、React、TypeScript 和 SQLite，Agent 执行基于 Claude Agent SDK。当前优先支持 Linux x64；Windows 和 macOS 仍处于候选构建阶段，尚未完成平台验收。模型连接需要可用的本机网关及相应账号配置。

静态设计参考见 [prototype/](prototype/index.html)，产品范围与进度见[桌面路线图](openspec/roadmaps/build-atelier-desktop/roadmap.md)。

## 桌面版

Linux x64 本地样包在 `dist/linux/`。Arch/Omarchy 可在仓库根目录运行 `sudo pacman -U ./dist/linux/atelier-0.2.0-1-x86_64.pkg.tar.zst`，然后从应用菜单打开 atelier。便携版可用 `tar -xf dist/linux/atelier-0.2.0-linux-x64.tar.zst -C <空目录>` 解包，从该目录运行 `./atelier/atelier`。包内含 Electron、Node 24.21.0、SQLite、SDK CLI、Shunt 0.64.0 和静态资源。当前本地候选面向 Arch/Omarchy，Shunt 需要 glibc 2.39 或更新版本。

发行版的数据默认写入 `$XDG_DATA_HOME/atelier`（默认 `~/.local/share/atelier`），浏览器 profile 位于该目录下的 `desktop-profile`。可通过绝对路径 `ATELIER_DATA_DIR` 选择其他数据根。同一数据根使用单写者锁。

迁入旧版数据时先退出旧工作台，启动 `atelier --import-data` 并选择包含 `atelier.sqlite` 的目录。若默认位置已经有工作区，使用 `ATELIER_DATA_DIR=/新工作区的绝对路径 atelier --import-data`。目标目录在迁入时创建。向导显示回退副本位置，项目、会话、附件和交付物记录随数据库迁入。网页使用新 profile，打开网站后可重新登录。

构建机安装包依赖 `makepkg`、`pacman`、`bsdtar`、`tar`、`zstd` 以及固定版本 Node 和 Shunt 的可执行文件。在项目根执行 `ATELIER_BUILD_NODE=/绝对路径/node-v24.21.0/bin/node ATELIER_BUILD_SHUNT=/绝对路径/shunt npm run package:linux`。`dist/linux/SHA256SUMS` 提供资源清单与工件校验，`release.json` 记录运行时版本。安装态验收入口为 `npm run smoke:linux -- --help`。

开发版从项目根运行 `npm run desktop`。先读[项目协作规则](AGENTS.md)。[桌面路线图](openspec/roadmaps/build-atelier-desktop/roadmap.md)和[发行选型记录](docs/decisions/2026-11-20-linux-release.md)说明当前阶段的交付范围。

## 启动

本轮验证环境：Node **24.21.0**、npm 11.19.0、Claude Agent SDK **0.3.332** / CLI **2.1.332**、Shunt **0.64.0**。Node 最低要求 24，推荐使用已验证版本。

```sh
git clone https://github.com/CoderLambert/atelier-handoff.git
cd atelier-handoff
# 使用 Node 24；推荐 24.21.0
npm ci
npm start
```

`npm start` 会先用 Vite 构建前端，再启动本地工作台。打开 **http://127.0.0.1:4317**。

开发时在两个终端分别运行 `npm run dev:server` 和 `npm run dev`，打开 **http://127.0.0.1:5173** 使用前端热更新。Vite 将 `/api` 代理到 `ATELIER_PORT`，默认为 `4317`。服务重启会中断未完成的运行，并保留历史。

Linux 安装版默认随窗口启动内置 Shunt。首次授权可在「模型与网关设置」点击「登录 ChatGPT」，通过系统浏览器完成。已有 Shunt 账号目录会被复用；新安装使用工作台数据目录下的 `shunt/accounts`。`shunt/shunt.toml` 和账号目录选择会在重开及更新后保留。也可在设置中切换到外部网关。开发桌面会复用 `dist/linux/atelier/resources/shunt/shunt`。该构建产物缺失时，默认连接 `http://127.0.0.1:3001`。显式设置 `ATELIER_GATEWAY` 时，桌面启动使用外部网关配置。

首次进入页面，点击「选择文件夹…」打开系统目录选择框，选好后点击「绑定项目」。系统选择框需要服务从安装了 Zenity 的 Linux 桌面会话启动。也可手动输入绝对路径。配对的 Linux 桌面新建普通会话默认「本机信任」，以当前登录用户权限使用 Shell、文件和网络。输入框的运行模式可切换到只读、受控修改或全工具自动化。既有会话沿用其保存的选择。

## 已可使用的功能

- **项目与会话**：项目绑定、文件浏览、会话搜索、独立草稿、重命名、归档/恢复和删除。
- **真实执行**：流式文本、工具详情、按轮保存的 Run、背景运行状态、停止与只读恢复分析。
- **受控文件操作**：真实差异和操作原因，单次允许/拒绝，基线变化拒绝、审批过期、停止后迟到批准无效。同一项目的运行串行，避免应用内并发覆盖。
- **命令执行**：本机信任使用 SDK 原生 Bash。项目受控模式通过 Linux bubblewrap 执行命令，逐次审批、禁网，单次最长 60 秒。
- **上下文与附件**：项目内文本预览和选择，真实 UTF-8 文本上传，按会话隔离，发送时冻结引用。
- **成果**：Agent 明确发布的真实文档保存为不可变快照，可预览、下载并跳回来源运行；不扫描整个项目冒充成果。
- **恢复与记录**：SQLite 保存消息、运行、审批和事件；SSE 断线补齐；重启后保留历史并区分 interrupted。会话可以续接，旧的在途操作不会自动批准。
- **计划与用量**：仅显示 Agent 实际调用结构化计划工具产生的步骤；显示真实可得 token 数据。费用未知时明确显示未知，SDK 估算不冒充账单。
- **长内容**：会话/全局列表分页，工具输出保留预览并支持完整内容分页及下载；不靠等待时间生成进度。

## Git 看板与开发会话

安装系统 Git 后，可从项目选择器或会话顶部打开 **Git**，在右侧查看文件变动、本机分支、提交历史和工作树。拖动左侧分隔条调整面板宽度，点右上角的全屏按钮展开，按 Esc 可返回侧栏。差异预览显示语法高亮、增删行和原、新行号。文件列表按暂存状态分组，并显示文件类型和所属目录。

点击 **AI 提交**，工作台先读取所选工作树中可处理的已暂存、未暂存和未跟踪变更。可以选择模型、填写可选的补充要求，再开始 AI 规划。未选择模型时使用工作台默认模型，不会修改聊天或工作台的默认设置。

分组完成后，在 **告诉 AI 怎么改** 里继续补充，例如「把剩下的 OpenWiki 变更合成一组，并改写第一条标题」。每次发送用所选模型修改当前草稿，可查看修改记录并撤销最近一次修改。审查摘要后可确认创建本地提交，也可展开详情手动调整分组、顺序和说明，核对逐组差异。普通文本可按独立变更块分组。受保护文件、冲突及无法安全处理的项目会明确显示，须排除或先在本机处理。模型不可用时可手动分组。工作树或暂存区在核对后发生变化时须重新核对，中断操作可在 Git 面板查看恢复或安全放弃入口。此流程跳过 Git hooks，要求签名时请使用本机 Git。提交在本地创建，由用户决定是否推送。

使用 **新建开发会话** 预览分支、基线和目录。默认从当前工作树的本机 HEAD 创建独立工作树，原目录的未提交文件留在原处。也可选择本机分支、提交或在干净的项目原目录切新分支。独立工作树使用受控修改模式，可在输入区显式选择本机信任。

归档最后一个会话时，Atelier 先核对快照再回收目录。忽略的文件会保留目录，可在 **工作树** 中逐项将可再生缓存标记为可重建后重试。重新打开归档会话时，选择 **恢复工作树**，恢复暂存区和文件后继续发送。原分支已移动或被占用时，需确认一个新分支。关闭窗口会保留工作树。

受管工作树在应用数据根下。若数据根在已绑定的项目目录内，独立工作树创建会提示路径重叠。技术取舍、数据迁入和回退见 [Git 工作树决策](docs/decisions/2026-11-24-git-development-sessions.md)。

## 查看执行明细

运行时在助手消息的「执行明细」中查看命令，展开一行可阅读参数、状态和已返回的输出。已完成的会话可展开历史明细。原生 Bash 回执提供的 stdout 和 stderr 分开展示，受控命令展示合并输出。长输出通过「查看完整输出」分页读取或下载。

工作台默认把导航栏以外的空间留给会话。打开右上角「浏览器」才显示网页面板；「变更记录」可按需查看会话审批和差异。「执行轨迹」展示所选运行的事件、工具回执及用量。

## 会话子代理

直接在聊天中交代任务。主助手可自动把独立工作分给子代理，传入完成工作所需的上下文，并在收到结果后汇总答复。同批前台委派沿用 Claude CLI 与锁定 SDK 的原生调度，工作台不另设子代理数量上限。试试「分别检查导入和导出模块，修复发现的问题并汇总变更」。需要审阅每次修改时选择「受控修改」。

在该轮消息的「子任务」处逐项展开，查看运行状态、耗时、工具与结果。审批弹窗标出发起操作的子任务。完成后可在原消息或「执行轨迹」中查看同一份记录。点击「停止」结束当前轮及其在途子任务，未处理的审批随之失效。

子代理继承本轮模型和项目授权。探索任务可读项目与搜索指定站点，执行任务还可使用本轮授权的文件修改与隔离命令工具。站点搜索通过本轮模型网关执行，返回可核对的同域名来源。共享浏览器、其他外部服务和交付物由主助手操作。运行时可用 `ATELIER_DISABLE_SUBAGENTS=1` 关闭新的委派。

## 本机执行与恢复

本机信任允许访问当前系统账户可以读写的文件。桌面运行时继续管理模型连接、内置浏览器授权、成果和停止操作。原生工具用于命令、读写、文件搜索和打开已知网址。本机及当前项目的 `.claude/skills` 可以按需调用，工作台已有的项目技能通过原有插件加载。新运行记录 `native-v1` 或 `project-v1`，历史队列沿用提交时的权限。设置 `ATELIER_NATIVE_EXECUTION=0` 后重开桌面可关闭本机执行。

执行器共享本轮的进展记录。重建上下文时，工作台从此前各轮提取用户要求与更正、来源链接、工具回执及待核对的副作用。每类资料独立保留早期记录和最近记录，超出摘要预算时注明省略情况。原工具输出可按证据 ID 分段读取。任务的重复查询、持续错误和等待通过「执行轨迹」查看。本机信任默认用 `feedback` 将停滞提示交给模型。设置 `ATELIER_HARNESS_PROGRESS=observe` 可切换为记录观察结果，`pause-branch` 允许在反馈后持续确定失败时停止对应子任务。手动停止和关窗按运行回收可追踪的命令和子进程。

运行 `node --import tsx scripts/smoke-native-harness.mts` 可在独立 Electron profile、临时项目及回环模型下验证本机文件修改、命令停止和重启后核对结果。

## 项目智能体

打开侧栏「智能体」，选择项目并使用「资料整理助手」模板，或自己填写任务说明和开场任务。按需选择内置能力、项目 Skill 和具体 MCP 工具。新建智能体默认只读，创建时也可选择「受控修改」。从卡片的「开始会话」进入绑定版本的会话。会话以只读开始，允许受控修改的智能体可在输入框切换模式。

编辑保存会创建新版本，已有会话保留原配置。依赖升级、停用或撤销授权后，在智能体编辑器中检查依赖并保存新版本。受控修改模式中的文件操作、命令和需审批的 MCP 工具沿用逐次审批。

## 扩展与对话调用

在侧栏打开「扩展」并选择项目。Skills 和 Commands 分别管理 `SKILL.md` 与 Markdown 指令模板。导入时可预览内容。保存并启用后，在对话输入框输入 `/` 选择，或直接发送 `/summarize src/` 这类已经登记的指令。模板中的 `$ARGUMENTS` 会替换为用户输入的参数。

「从公开来源导入」支持 GitHub 仓库或文件链接。Skills 与 Commands 标签可以浏览相应 Markdown 文件。MCP 标签还可以搜索官方 MCP Registry，或从 GitHub 导入 `.mcp.json`、`mcp.json` 和 `server.json`。预览并导入后，卡片上的「检查更新」会按原来源检查新版本，预览后可以应用更新。

在扩展页打开「Skill 市场」可浏览 SkillHub 的推荐和分类，搜索并预览后导入当前项目。

已启用且允许自动调用的 Skill 会按项目提供给 Agent SDK。模型根据名称和描述决定是否使用，调用时读取本地固定版本的正文。可在 Skill 卡片上改为仅手动调用，或使用 `/` 明确选择。执行轨迹会分别显示候选情况和实际调用版本。Skill 沿用本轮项目权限。

桌面工作台右侧「浏览器设置」可开启「允许 Agent 使用内置浏览器」。项目授权一次后，桌面对话可使用网页导航、读取和截图。让 Agent 点击网页时保持右侧浏览器面板打开。受控修改模式下，点击与输入按操作审批。人工接管优先，交还时 Agent 接续所选的标签。

点击桌面会话中的网页链接，可以在右侧内置浏览器的新标签打开，也可以交给系统默认浏览器。内置标签打开后由你操作，可通过「交还控制」交给 Agent。

人工浏览时下载的文件保存到系统「下载」目录，同名文件会加序号。网站使用编号文件名时，如果能匹配到唯一的链接标题，工作台用该标题和原文件后缀保存。浏览器工具栏的下载按钮可查看进度和文件保存路径。完成后可用 FileVista 预览 Excel、PDF、图片、文本，或使用系统应用打开和在文件夹中定位。

输入区的「运行模式」随当前会话保存。选择「全工具自动化」后，该会话发送的任务会自动审批已获授权的文件、沙箱命令、Skill、MCP 和浏览器操作，审批决定可从执行轨迹查看。绑定智能体按其授权执行。从输入区发送时，「全网搜索 Skill」的单次付费上限为 0 分。

点击发送键旁的模型名称可直接选择模型。目录包含 Shunt 路由；检测到 ChatGPT Plan 路由时，也会读取本机 Codex 的可见模型。支持跟随工作台默认值或手动输入完整模型 ID。旁边的「深度」选择器用于设置推理档位。两项选择随会话保存并用于后续发送，切换模型时恢复默认深度。Shunt 路由固定深度时，界面会显示该档位。

MCP 页支持 Streamable HTTP 和 stdio。导入 MCP 配置后可核对地址、启动参数及凭据环境变量，再测试连接、选择允许的工具并启用。输入 `#` 选取本轮要用的工具。需审批的工具可在「受控修改」模式中使用。

SkillHub 支持预览并安装完整技能包。安装后点「到对话中使用」，或在输入框用 `/` 选中。读取包内文档可在只读模式使用。执行包内 Python 需要 Linux bubblewrap、受控修改模式和逐次审批。已审核的「全网搜索」v1.0.3 通过固定服务连接完成报价、确认并提交搜索、取回原请求结果，PDF、Markdown 和 CSV 会保存在交付物中。

## 本机配置与数据

可参考 [.env.example](.env.example)。根目录 `.env` 自动加载但不会进入 Git；不要把真实凭据提交到仓库。首次默认配置来自环境变量，之后网页保存的模型/网关设置优先。

| 配置 | 默认值 |
| --- | --- |
| ATELIER_PORT | 4317，仅监听 127.0.0.1 |
| ATELIER_GATEWAY | http://127.0.0.1:3001 |
| ATELIER_MODEL | gpt-6.1-sol |
| ATELIER_GATEWAY_TOKEN | local-placeholder，仅供当前本机 Shunt |
| ATELIER_DATA_DIR | 本项目 .data/ |

`.data/` 包含 SQLite、SDK 会话、附件、成果快照和完整工具输出，已从 Git 排除。停服后可备份整个目录。会话删除会删除其应用历史与关联文件，但不会删除项目源文件。不能同时用两个服务进程打开同一个数据目录。

会话详情使用 Drizzle 按会话索引读取数据。SQLite v6 从已有 JSON 记录派生会话归属列，保留原来的消息顺序。备份和回退步骤见 [ORM 架构决策](docs/decisions/2026-11-21-orm-architecture.md)。

## 当前边界

- 首版只面向本机单人使用，不提供团队账号、远程部署或后台无人值守任务。
- 附件只支持列明的 UTF-8 文本类型，单个最多 1 MiB；单轮附加上下文与附件合计最多 128 KiB。二进制、链接、凭据目录及过大文件有明确拒绝提示。
- 项目受控文件操作采用目录校验、单项目执行锁、审批基线复核与临时文件替换。它不是整机 OS 沙箱，也不保证与任意外部编辑器之间的文件竞争绝对原子。
- 同权限与相同模型配置下使用 SDK resume。切换权限范围/模型时，新建 SDK 上下文并带入应用保存的历史，避免沿用旧工具范围；本机执行恢复时会带入有界的近期对话与证据指针，历史过长时标明节选。
- 停止不回滚已经发生的修改。重试入口会新建一个只读分析 Run，避免直接重放写入。
- 任务默认持续运行到完成或手动停止。可在「模型与网关设置」开启任务执行上限并设置总轮数与总时长。计费搜索继续使用其单次费用上限。
- 当前会话使用完整消息快照刷新；超长会话的虚拟列表、性能调优和更细致的工程质量建设留到后续。
- Anthropic 不提供经网关运行非 Claude 模型的官方支持。本项目的兼容结论限定于记录的实际组合；ChatGPT 套餐的真实费用无法从 SDK 估算可靠推出。
