02 / PRODUCT

产品定位与用户目标

面向个人开发者的 AI 工作台，底层封装 Claude Agent SDK。用户在自己授权的项目目录中委托 Agent 阅读代码、分析问题、提出修改，在必要时审批文件操作与命令执行，最终获得可追踪的过程与可复用的成果。

核心价值：看得懂当前进展，知道 Agent 准备做什么，能够控制关键操作，并找回任务结果。

  • 代码分析：阅读现有实现，定位边界条件，提出可执行建议。
  • 受控修改：展示改动范围，由用户确认后执行并报告实际结果。
  • 文档整理：根据项目内容生成说明、报告或其他明确的交付物。
  • 持续工作：在同一项目和会话中继续追问，恢复历史与未完成任务。

首版假设为个人、本机项目场景。团队协作、组织权限、多租户部署、多 Agent 调度、自动发布与后台无人值守任务暂不纳入首版。模型切换、多供应商、MCP / Skills 管理也不应仅因界面出现配置入口就视为已承诺能力。

05 / USER FLOWS

核心交互流程

首次使用与正常任务

配置可用的执行环境 → 选择并授权项目 → 创建会话 → 输入任务 / 附加上下文 → 服务端创建消息与运行 → 展示真实文本和工具事件 → 如需权限则等待审批 → 执行终止 → 展示实际结果与成果

首次配置和项目选择页面尚未设计完整。开发需补齐未配置、连接失败、目录失效与空工作空间状态。示例工作区名、Lambert 身份与 orbit-web 项目不是正式账号或项目系统。

文件修改与审批

Agent 请求操作 → 服务端冻结操作与文件基线 → 页面展示范围、目的与差异 → 用户查看详情 → 允许 / 拒绝 → 服务端幂等记录决策 → SDK 执行或处理拒绝 → 页面展示真实结果

拒绝一次操作后，Agent 可以解释、给出替代方案或结束当前运行。拒绝不是永久结束会话，也不自动等于整个任务失败。

连续追问与跨会话切换

在同一 Session 下为每次提交创建新的 Run，不覆盖前一轮执行轨迹与交付物。切换会话不停止后台任务；会话列表继续更新。输入草稿与附件草稿按会话隔离，不能把一个会话的文件带入另一个会话。

异常与恢复

断线 / 工具失败 / SDK 错误 → 保留已有内容 → 显示故障阶段和已发生操作 → 查询服务端状态 / 补齐事件 → 用户选择重试、重新发起或停止

前端断网不代表运行失败。只有服务端确认的终态可以改变运行终态。SDK 进程退出或服务重启导致的中断不能伪装为用户主动停止。

成果闭环

运行结束后展示结果摘要；只将明确生成的成果登记为 Artifact。用户可在当前会话或全局交付物中预览、下载和回到来源运行。项目里的全部源码不自动成为交付物。

06 / STATE MODEL

状态与并发规则

目标领域对象与状态
对象建议状态关键约束
Sessionactive / archived长期容器；展示最近 Run 的状态，不永久标记“已完成”
Runqueued / running / awaiting_permission / stopping / completed / stopped / failed / interrupted终态不能由浏览器计时器推测；持久化真实终止原因
ToolCallqueued / running / awaiting_permission / succeeded / failed / denied / canceled成功必须有真实结果；拒绝保留决策与原因
PermissionRequestpending / allowed / denied / expired / canceled终态决策不可重复应用；原子状态更新
Artifactavailable / unavailable引用可追踪的文件版本；不可访问有明确解释
UI 连接connecting / connected / reconnecting / disconnected与 Run 状态分离，连接中断不等于任务已停止

queued → running ↔ awaiting_permission → running → completed / failed
活动运行 → stopping → stopped（确认终止后）
进程丢失或不可恢复重启 → interrupted（记录已完成操作）

  • 首版同一会话只允许一个活动运行；重复提交返回明确冲突，不产生第二次副作用。
  • 不同会话可独立执行；并发上限作为服务端配置，达到上限进入队列或返回忙碌状态。
  • 同一项目中的冲突写入需串行化或验证文件基线，即便来自不同会话也不能静默覆盖。
  • 执行中保留输入草稿，提供持续可用的停止入口；首版不支持未设计的中途插话或隐式队列。
  • 等待审批时，输入内容保留并提示先处理审批，不能丢弃草稿或把文本当成权限决策。
  • 停止与完成竞态以服务端最终结果为准；停止不撤销已发生写入。
  • 同一运行可多次请求权限，每个请求独立；多个请求需可逐个处理，不能复用一个固定卡片的数据。

原型的 idle、waiting、done、denied 等是 UI 演示状态，不能直接作为正式领域模型。尤其应将“操作被拒绝”从运行整体状态中分离。

07 / PERMISSION & DIFF

审批与真实文件差异

审批界面必须回答：准备做什么、影响哪里、允许的范围是什么。首版提供“允许本次”和“拒绝本次”；始终允许、自动审批、批量放行需另行设计。

不同操作的审批信息
类型必须展示决策后的要求
修改文件授权范围内的路径、文件基线、真实差异、目的、文件数文件或操作发生变化时重新确认；只执行已审批操作
创建 / 删除对象路径、内容摘要或删除范围、恢复能力说明不得把删除呈现为普通编辑；记录实际结果
执行命令命令原文、工作目录、目的；敏感参数脱敏命令不得在前端审批后被静默替换；取消与超时有实际处理
其他工具工具名称、关键参数、访问对象与权限范围工具适配层校验，不能仅依赖按钮状态
  • PermissionRequest 绑定 runId、toolCallId、操作快照与有效期。服务端验证当前用户或本地应用身份对该项目的权限。
  • 前端只提交决定，不直接执行文件操作；按钮禁用不能代替服务端授权。
  • 双击、网络重发和多窗口操作只能生效一次；过期、已处理或已取消的请求返回明确状态。
  • 停止运行会取消其待审批请求；迟到的允许请求不能重启运行。
  • 读取、写入、下载都必须验证路径范围，处理符号链接和目录穿越，不接受浏览器传入任意绝对路径。
  • 操作过程中失败要报告部分完成情况；“失败”不保证没有任何写入。

待 SDK 验证：当前版本权限回调是否提供可计算准确 diff 的信息、如何等待异步用户决策、如何取消等待。若无法在写入前取得可靠 diff，应补充受控执行 / 预演层，或展示准确操作预览并说明范围，不能使用固定示例替代真实差异。

应用服务 ↔ 持久化存储 / 附件与成果服务

建议职责拆分，尚未创建这些模块
模块负责不应负责

建议正式开发使用 TypeScript 维护共享 DTO 与状态联合类型，界面可以按现有组件边界迁移到选定前端框架。当前没有选定服务端框架、数据库、运行载体或 SDK 版本；这些是接入前的技术决策，不应将建议写成已落地依赖。

密钥与提供商认证留在服务端受控配置，不进入网页源码、消息内容、事件日志或下载文件。本机服务也需限定监听范围、校验请求来源与应用身份；远程使用会增加部署和用户鉴权需求，不在首版假设中。

Runid、sessionId、triggerMessageId、status、startedAt、endedAt、reason、error一次提交对应一次运行；每次重试另建 Run 并关联来源
ToolCallid、runId、name、inputSummary、status、outputRef、startedAt、endedAt记录真实工具结果；大输出分页或按需加载
PermissionRequestid、runId、toolCallId、operationSnapshot、baseFingerprint、status、expiresAt、decidedAt原子决策；操作与基线匹配；保留审批记录
Attachment / ContextRefid、sessionId、name、mimeType、size、sourceType、status、storageRef区分上传完成、可解析、已附加与已读取；关联特定请求上下文快照
Artifactid、runId、projectId、name、mimeType、size、storageRef、fingerprint、availability明确来源运行与文件版本；下载时再次校验访问权限
UsagerunId、model、inputTokens、outputTokens、cacheUsage、costEstimate、pricingVersion字段缺失用 null，不伪造 0；费用估算标明币种、时间与计价依据
RunEventeventId、runId、seq、type、timestamp、payload、schemaVersion序号在运行内递增；先持久化再可重放；敏感信息脱敏

服务端是消息、运行、权限与成果的事实来源。浏览器保存草稿、展开状态与显示偏好；浏览器缓存失败时页面仍可使用，但不能承诺跨刷新保存。附件草稿按会话隔离，提交时冻结实际使用的上下文列表。

持久化位置由选定部署环境的配置与数据目录合同决定，本说明不指定宿主数据目录。备份、迁移和保留策略需在选择数据库后定义。

  1. 每个运行维护单调递增 seq，事件具备稳定 eventId；客户端按运行去重，不能全局混用序号。

14 / ACCEPTANCE

验收与测试策略

以下全部为待实施验收要求。正式开发应同时覆盖应用状态、HTTP 集成、SDK 适配及关键用户流程。

  1. A01 真实任务：绑定授权项目，新建会话，提交任务，接收真实流式回复并得到明确终态。
  2. A02 会话切换：执行中切换会话再返回，消息、草稿、附件归属和运行状态一致；后台任务不因切换被停止。
  3. A03 拒绝审批：写入前展示准确范围；拒绝后对应操作不发生；会话可继续。
  4. A04 允许审批：重复点击与请求重发只执行一次；文件内容与审批快照一致；基线变化要求重新确认。
  5. A05 停止：显示 stopping，真实终止后显示终态；已发生变更保留并可解释；停止后迟到审批无效。
  6. A06 断线重连：丢失连接后查询服务端事实、补齐事件，无重复消息、工具或副作用。
  7. A07 刷新与重启：刷新恢复历史；服务重启后区分可恢复与 interrupted；不得将未知运行误标为用户停止。
  8. A08 成果：下载与预览来自真实成果，内容和版本一致；不存在或无权限时显示原因。
  9. A09 可恢复错误：SDK 未配置、目录失效、上传失败、工具失败、权限过期都有具体处理入口。
  10. A10 适配与键盘：375 / 768 / 1024 / 1440 宽度、矮屏、200% 缩放可完成关键操作；焦点可见、无意外陷阱，抽屉与弹窗可正确返回。
  11. A11 数据一致：连续两轮分别保留消息、工具、审批与成果；历史排序根据真实更新时间。
  12. A12 边界：目录穿越、符号链接越界、伪造项目引用被拒绝；凭据不出现在日志、消息与下载内容中。
  13. A13 真实缺失：没有结构化计划时不造计划；没有 usage 时显示暂无；估算费用有计价说明。
  14. A14 状态冲突：多窗口审批、停止与完成竞态、同项目并发写入不会静默覆盖或重复执行。
