# atelier 与 Claude Code CLI 测试记录

本页记录真实模型对照和本地诊断。每次测试后追加一条记录，保存用例、版本、模型路由、推理档位、通过条件、结果、失败与证据。结论以覆盖过的场景为限。每次任务评分使用最终交付物、独立验证和磁盘状态，恢复机制及耗时单列。

## 会话并行与插话

这组改动让用户能核对长时间运行的 Bash 的真实结果、在工具运行期间向主会话补充指令，以及在同一工作目录运行多个独立会话。对齐基准为 Linux 上锁定的 Claude Agent SDK 0.3.332 和随附的 Claude Code CLI 2.1.332。

| 操作 | Atelier 行为 | 技术决策 |
| --- | --- | --- |
| Bash 长时间运行 | 本机信任使用 SDK 原生 Bash 和前台时限。超时可由 SDK 转后台，用户也可从工具详情选择「转到后台」或「停止命令」。以前台退出回执或匹配的后台终态确认结果，缺少终态时显示待核对。 | [Bash 生命周期和日志](decisions/2026-11-25-claude-bash-and-parallel-sessions.md) |
| 运行中补充指令 | 普通兼容消息在主会话工具检查点发送。按 `Ctrl+Enter` 或点击队列中的「立即插入」，将可转后台的前台 Bash 或同批子代理交给 SDK 继续执行，主会话先收到新指令。子代理完成后交回报告，也可单独停止。 | [子代理交接和结果回送](decisions/2026-11-25-claude-subagent-insertion.md) |
| 在相同目录继续另一项工作 | 切到同一工作目录的另一个会话即可发送。各会话并行时分别持有自己的 SDK 进程、消息、审批和取消。单会话串行，工作台全局最多三个活动会话。父子目录重叠、Git 目录操作及归档继续检查目录租约和占用。需要隔离文件变更时可创建独立工作树。 | [执行席位及目录规则](decisions/2026-11-25-claude-bash-and-parallel-sessions.md) · [Git 开发会话](decisions/2026-11-24-git-development-sessions.md) |

Atelier 的「立即插入」按一条消息操作。可插入的是与当前运行的模型、推理档位、执行模式、工作目录和授权范围兼容的纯文本消息。新增上下文、附件、扩展选择以及 `/` 和 `!` 命令的请求按下一轮任务处理。需要结束当前轮才能发送时，队列提供「停止本轮并发送」。受控模式按会话的审批和执行检查点处理任务。同目录的受控写入仍按目录串行并在执行时复核基线。Claude CLI 的队列批量发送语义见[交互文档](https://code.claude.com/docs/en/interactive-mode#when-claude-code-sends-what-you-queued)。

### 回执与回退

运行时逐调用使用 `backgroundTasks(toolUseId)`，以 `stopTask(taskId)` 停止指定原生任务。回执按所属 SDK 会话、调用和任务身份归档。前台 Agent 通过完成回调交回报告，后台 Agent 通过任务终态交回摘要。早到的完成通知在后台交接确认后入账。主会话先展示新答复，并保持 SDK 连接收取后台结果。分支工具沿用原子代理的身份和授权。

两项改动使用原有会话、工具和子任务记录。可按各决策的回退范围恢复此前的 Bash 控制、目录执行席位或前台子代理等待。排查时从会话的「执行轨迹」核对本轮工具回执、子任务报告和停止结果。

## 2026-11-23 · 长上下文自动压缩后的重启续接

**双方均 2/2 通过。** 四次都观察到真实 SDK `compact_boundary`，重启后沿用原 SDK 会话，交付文件逐行匹配。atelier 的压缩后续接结果与 CLI 一致。

| 自动压缩窗口设定 | 执行入口 | SDK 压缩前 → 压缩后 token | 压缩用时 | 重启后续接用时 | 成果 |
| ---: | --- | ---: | ---: | ---: | --- |
| 120,000 | atelier | 99,131 → 10,342 | 23.7 秒 | 15.4 秒 | 通过 |
| 120,000 | Claude Code CLI | 94,354 → 8,723 | 25.9 秒 | 18.9 秒 | 通过 |
| 140,000 | atelier | 114,929 → 10,447 | 23.8 秒 | 17.6 秒 | 通过 |
| 140,000 | Claude Code CLI | 110,074 → 8,622 | 24.1 秒 | 17.1 秒 | 通过 |

压缩前后 token 取自 SDK 边界元数据。窗口设定是触发配置值，实际会话 token 由 SDK 报告。压缩用时为边界记录值，续接从提交最终指令到终态，不含重启准备时间。四次正式运行共产生 72 次成功模型请求。[逐项证据与请求记录](evidence/agent-eval/2026-11-23-context-compaction.json)

### 测法与判分

1. 两边沿用前轮的运行时版本、模型和 `medium`。应用通过正常 HTTP 会话入口运行。隔离启动器只在测试沙箱内为两边的原生 CLI 进程设置同一个 `CLAUDE_CODE_AUTO_COMPACT_WINDOW`，分别跑 120,000 与 140,000。模型由本机网关回执核对。[自动压缩配置](https://code.claude.com/docs/en/env-vars)
2. 首轮从临时文件读取事件编号及行号，写入一次 `prepared` 收据，并指定七行交接格式和冻结操作。随后以相同顺序输入 8 批或 10 批合成诊断，每批 430 条确定性长记录。第四批前更正处置政策。各轮输入哈希、用例种子、源码指纹、各轮耗时和网关用量留在证据中。
3. SDK 写下 `trigger: auto` 的边界后继续输入余下诊断。结束会话进程，移走旧证据文件并更新磁盘状态，再从原对话提交通用续接指令。最后一轮提示只要求继续交接并检查磁盘状态。双方重启后的首个请求仍比各自压缩前历史短。两次 atelier 运行均从已压缩的原 SDK 会话续接。
4. 判分检查自动压缩前至少 80,000 token、压缩后低于其一半、重启续接请求仍缩短，并核查真实交接文件的旧证据及行号、最新政策、早期冻结要求、当前磁盘状态和收据。程序核对未重复执行准备操作，项目文件保留预期状态。两对的任务输入按轮逐一比较哈希。[逐项证据](evidence/agent-eval/2026-11-23-context-compaction.json)

### 预检与范围

- CLI 的短历史预检可用 `/compact`，记录 `trigger: manual`。同样输入在 atelier HTTP 入口返回 `EXTENSION_UNKNOWN`，提示找不到 `/compact`。正式评分使用 SDK 自动压缩，两次预检单独记录。[预检结果](evidence/agent-eval/2026-11-23-context-compaction.json)

## 2026-11-23 · 上下文请求体积拆账

同版本 SDK 和 CLI 在隔离目录发两条相同短任务，由本地回环夹具返回固定 `ACK`。工具与提示由真实执行入口组装。10 组配置共采集 20 条请求，真实推理调用为零。下表为无规则文件的首轮请求，单位是 UTF-8 JSON 字节，各字段单独序列化。供对照的上轮真实网关 token 计数单列在证据中。[逐条测量](evidence/agent-eval/2026-11-23-context-payload-audit.json)

| 入口 | 工具数 | 整体 | 工具定义 | 顶层 `system` | `messages` |
| --- | ---: | ---: | ---: | ---: | ---: |
| CLI · 上轮限制的六个工具 | 6 | 18,403 | 10,637 | 5,817 | 1,601 |
| atelier · 本机执行 | 14 | 38,188 | 22,411 | 6,690 | 8,739 |
| CLI · 默认工具 | 21 | 71,132 | 56,808 | 5,989 | 7,987 |

相对六工具 CLI，atelier 的请求多 19,785 字节。工具定义多 11,774 字节，`messages` 多 7,138 字节，顶层 `system` 多 873 字节。`messages` 的主要差额来自 SDK 附带的环境区块，内容包括运行环境、可用技能、Agent 和 MCP 等信息。默认工具 CLI 的首轮请求更大，因此上一轮约 4,200 token 的差额只描述了当时的工具配置。字节比例无法换算为 token 占比或账单比例。[逐条测量](evidence/agent-eval/2026-11-23-context-payload-audit.json)

**发现一处可去重的规则传输。** atelier 把 `AGENTS.md` 和 `CLAUDE.md` 明文拼进每轮用户消息。合成项目的 `CLAUDE.md` 含 `@AGENTS.md` 时，SDK 还会在同一轮插入一次标为 Read 结果的文件块。只把 `@AGENTS.md` 改成普通文件名，首轮 `messages` 少 9,542 字节，第二轮累计少 19,096 字节，显式规则仍在。相同导入写两遍时，单轮仍只出现一次额外读取，下一轮会再读一次。当前仓库的 `CLAUDE.md` 有两个这样的引用，应用自有规则区块实测 8,980 字节，实际重复量随文件内容而变。[当前注入代码](../server/native-harness.ts#L55) · [请求构造](../server/agent.ts#L1949) · [对照结果](evidence/agent-eval/2026-11-23-context-payload-audit.json)

建议的首次验证是只处理应用已注入的同一文件引用，保留规则正文、其他文件引用和 SDK 压缩行为。验收可比较两轮规则副本数，再用规则生效与压缩续接用例核对成果。本轮未改应用行为，也未测实际 token 节省或能力变化。

## 2026-11-23 · 本机执行的项目规则去重

atelier 把 `CLAUDE.md` 中独立的 `@AGENTS.md` 和 `@./AGENTS.md` 转为普通文件名，前提是本轮能把完整的 `AGENTS.md` 内联。两份文件仍共用 16 KiB 的读取预算。目标文件无法完整纳入时，继续发送原来的节选及 SDK 引用。其他文件引用继续按原方式解析。[实现](../server/native-harness.ts#L79)
