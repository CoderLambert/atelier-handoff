# atelier 本机首版完成记录

日期：2026-11-18。按用户“功能优先，先跑起来，再做工程质量”的要求，从 T01 继续实现 T02—T20。当前交付为可启动的个人本机版本，保留原有三栏视觉结构；原静态设计完整保存在 prototype/。

## 实际交付

- Node 24 + TypeScript 本机 HTTP 服务，SQLite 独立保存 Project、Session、Run、Message、ToolCall、PermissionRequest、Artifact、Attachment 和 RunEvent。
- 项目绑定、文本文件浏览与上下文选择，会话创建、搜索、分页、独立草稿、重命名、归档恢复与删除。
- 官方 Claude Agent SDK 0.3.326 / CLI 2.1.326，通过本机 Shunt 0.64.0 使用 gpt-6.1-sol；流式文本与工具结果真实接入页面。
- Read 与受控 MCP 工具：文件检索、单次审批的编辑/创建/删除、隔离命令、结构化计划和明确的成果发布。
- 准确的操作快照与基线校验，允许/拒绝/过期/取消/重复决策处理；停止后等待 SDK 和已开始的受控工具收尾，再宣告终态。
- 每会话与每项目单活动 Run，不同项目最多三个并行；重试新建只读分析 Run，不直接重放写入。
- SSE 事件持久化、游标补齐与重连；服务重启保留历史、旧运行标记 interrupted、旧审批失效；页面刷新本机令牌后继续使用。
- 真实文本附件、不可变成果快照、预览下载、全局运行来源跳转；工具长输出保留完整版本并按需分页/下载。
- 仅显示真实 update_plan 数据；token 字段有值才展示，费用口径未知时明确标注。窄屏抽屉、键盘标签、弹窗焦点、IME 与滚动跟随已接入。

一个前端子代理通过本机 Codex CLI 显式指定 **gpt-6.1-terra** 实现页面接线及第一轮交互修正；后端、最终修复、验收和 Git 操作由主会话完成。没有运行多代理编排或改动现有 Shunt/微信服务。

## 联调中修正的问题

- 初次从只读切到编辑时，模型仍沿用旧说明：现在权限/模型范围变化时新建 SDK 上下文并带入完整应用历史，同范围继续 resume。旧的首次问题运行仍保留在验收数据中，没有伪装成成功编辑。
- 流式事件使用尾沿防抖导致持续输出时不刷新：改为有界节流，旧请求不能覆盖新快照。
- 输入框保持焦点时切换会话，会保留前一会话的可见文本：现在按 sessionId 明确刷新输入框，并仍保护同会话的编辑。
- 模式按钮继承了原型隐藏样式：已补齐可见样式；新一轮保留用户选定模式，写入仍逐次审批。
- 服务重启后旧请求令牌失效：重连刷新令牌；明确 TOKEN_REQUIRED 时只重取令牌并重试一次。
- 工具输出只有短预览：完整文本单独保存，提供分页与下载。

## 当前限制与后续工程质量

功能清单 T01—T20 按个人本机首版范围完成；以下边界明确保留，不冒充企业级或无限制能力：

- 仅本机单人、文本附件/成果，不包含团队身份、远程部署、二进制编辑或桌面原生目录选择器。
- 当前会话完整快照刷新适合个人规模；超长历史虚拟化、压力测试、更多平台与浏览器、工程重构和 CI 可在使用反馈后推进。
- 文件操作不保证与任意外部进程竞争时绝对原子；同应用项目执行串行、审批前后复核和链接限制已实现。
- 命令依赖 Linux bubblewrap，无网络、最长 60 秒；不可用时明确关闭，不降级为无限制 shell。
- 普通在途 SDK 回调不能跨服务重启恢复；旧运行中断并取消旧审批，用户可重新发起只读分析。
- SDK 的美元估算不是 ChatGPT 套餐账单，实际费用未知；非 Claude 模型兼容性按当前实测组合记录。
- 真实调用只使用专门的临时测试目录，验收服务数据存放 .local/acceptance-data；正式入口使用 .data，二者分开。
