# 输入区 @ 文件直接引用与文件名高亮

参考 Cursor、Claude Code 与 Slack 等成熟工作台的行内引用交互，在消息输入区中支持键入 `@` 直接触发项目文件引用候选列表。选中文件后在光标处插入规范的 `@文件路径 `，并在界面与消息气泡中突出高亮文件名。支持按目录逐级下钻选择下一级目录与文件。

## 取舍与架构决策

1. **补全管线与键盘事件统一**：
   复用输入区现有的 `ExtensionPicker` 补全架构，将 `triggerAt` 触发符号扩展为 `/`（技能）、`#`（工具）与 `@`（文件）。避免在同一个 `HTMLTextAreaElement` 上注册多套独立的 `keydown` 监听器导致事件拦截冲突、中文输入法（IME）组合打断或 Enter 提交误触。

2. **`@` 引用与全量上下文 (`contextPaths`) 解耦**：
   - 对齐 Claude Code 与主流 Agent 的设计：输入框中的 `@文件` 为**行内路径精准引用**，主要作用是补全出规范路径并生成高亮徽标，方便用户指代具体文件。
   - **不强行将 `@文件` 塞入 `draft.contextPaths`**。因为 Agent 本身拥有完善的文件读取与搜索工具（`read_file`、`grep` 等），在收到带有明确文件引用的消息时，会自主按需调用工具分段查阅。
   - 解耦后彻底消除了大文件（如 MB 级数据、向量库 JSON、构建产物等）因强行全文拼入首轮 Prompt 触发 128 KiB 安全熔断（HTTP 413 `FILE_TOO_LARGE`）导致发送失败的问题，同时也避免了每轮对话被动烧掉海量 Token。
   - `contextPaths` 继续由「+ 上下文」显式弹窗管理，并在弹窗中对超出 128 KiB 的大文件进行拦截提示，避免误添加。

3. **目录逐级下钻与候选列表常驻**：
   - 候选列表同时包含目录项（`Folder` 图标与右侧 `ChevronRight` 指引）与文件项（显示格式化文件体积）。
   - 当用户选中目录项（点击或按 Enter/Tab）时，调用 `chooseDirectory` 将输入框词替换为 `@dir/`（带末尾 `/`，不带空格），光标移动至 `/` 之后。
   - 此时补全浮层**不关闭**，输入事件自动以 `@dir/` 为新前缀向服务端发起下级检索，即时展开该目录下的子目录与文件，支持用户连续点击/回车逐级下钻进入下一级目录。
   - 选中具体文件时，调用 `chooseFile` 插入 `@file ` 并关闭补全浮层。

4. **项目文件检索与安全边界**：
   在服务端提供 `GET /api/projects/:id/files?query=` 检索接口，复用现有项目的安全根目录鉴权与 `sensitive()` 黑名单检查，自动跳过 `.git`、`node_modules`、`.local`、`dist` 等敏感或构建目录。
   - 支持根据路径前缀精准解析当前目录（如 `src/` 直接从 `src` 读取），列出直接子目录与子文件。
   - 支持文件名与路径模糊前缀/子串匹配，优先排序文件名完全一致与前缀匹配的项，上限截断为 50 条以保证毫秒级响应。

5. **文件名多层级高亮呈现**：
   - **候选列表 (`.ext-completion`)**：采用 `[图标] [加粗文件名] [次级目录路径] [文件体积]` 排版，将文件名在视觉重心高亮展示，并将用户当前匹配的关键词用 `<mark className="ext-file-match">` 标记。在目录模式下匹配当前段落关键词。
   - **上下文标签栏 (`.composer-chips-bar`)**：已选上下文 chip 拆分目录前缀（低不透明度）与文件名（加粗主色前景），直观突出所选文件名。
   - **会话消息展示 (`.message-text`)**：用户发出的消息中的 `@文件路径` 引用自动识别并渲染为行内徽标 `.composer-file-mention-badge`，展示文件/文件夹图标、浅色路径与高亮下划线文件名。

## 验证计划

- `tests/picker-model.test.ts` 验证 `triggerAt` 对 `@` 符号的捕获、邮箱地址等非触发词的排除、`chooseFile` 对 `draft.text` 的规范路径替换且不污染 `contextPaths`，以及 `chooseDirectory` 逐级下钻与保留补全状态的行为。
- `tests/app.test.ts` 验证 `/api/projects/:id/files?query=` 的文件检索、目录递归检索与权限边界。
- `npm run check` 运行架构边界、i18n 完整性、UI 规范与严苛 TypeScript 检查。
- `npm test` 确保全量自动化测试全部通过。
