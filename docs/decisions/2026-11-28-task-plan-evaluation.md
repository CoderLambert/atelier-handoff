# 会话任务清单对照评测

用户要验证新版任务清单的内容质量和最终交付效果。原实验比较候选清单文本，真实 SDK 测试通过回环替身验证工具链路。仓库的 `harness-eval.mts` 用不同执行器比较工作结果，直接比较其结果会同时改变提示、工具和执行器。

## 取舍

1. 新建本地评测入口，复用 `harness-eval.mts` 的临时项目写入与快照。每个样例使用相同模型、采样设置、输入材料和执行指令，只替换规划系统提示及工具说明。旧版固定为 `ed2ba2f` 的两处规则，新版读取当前源码。规划输出由同一个模型的独立执行请求消费。这个设计便于观察规划内容对后续输出的影响，Atelier 真实交互中的单轮工具使用仍由已有 SDK 测试覆盖。
2. 之前使用 Anthropic 兼容端点的实验多数未返回计划工具参数。这里采用 Ollama `/api/chat` 的 JSON Schema，记录模型的原始响应、解析错误、实际执行输出和各项断言。借鉴 OpenAI `simple-evals` 的样例与评分分离，使用每个任务预先指定的检查。文本中难以用规则判明的语义保留原文供复核。 [Ollama 结构化输出](https://docs.ollama.com/capabilities/structured-outputs) · [OpenAI simple-evals](https://github.com/openai/simple-evals/blob/main/simple_evals.py)
3. HTML 交付写入隔离目录，用独立 Chromium 检查 375 和 1440 像素下的画面以及实际打印的 A4 页尺寸和页数。浏览器禁用页面脚本，所有资源请求由评测程序接管。模型可交付的文件名由样例指定。评测只访问回环端口上已安装的本地模型，不读取用户项目、`.env` 或模型账号配置。 [Playwright 请求路由](https://playwright.dev/docs/api/class-browsercontext#browser-context-route)

## 实施与验收

- 固定 HTML、数据计算、只读查因、材料缺失、取消 PDF 后交付 Markdown、简单问答六个样例。执行前定义清单要求与交付物断言。模型错误、越界写入、超时和漏项留在报告里。
- 增加评测入口和针对判分误判的测试。运行同一模型的新旧配对样例，保留原始结果与产物。运行仓库检查、测试和构建。结果在评测说明中记录命令、通过项及缺口。
- 回退时移除评测入口、样例、判分测试和说明。所有生产执行入口、权限和数据格式沿用现有实现。

## 运行结束前的验收与一次修正

用户选择了对有明确验收条件的任务在首次失败后允许一次修正，再对修正结果复验。首轮评测中浏览器的结果只写入报告，执行助手拿不到失败原因。工作台的两条计划写入路径也都接收模型提供的状态。SDK 的成功回执描述本轮正常结束，不能独立证明交付满足请求。

实施采用主运行的 SDK Stop 钩子。只从用户本人给出的明确条件提取可执行检查，使用本轮不可变成果及实际回复作为输入，有文件时读取并验证指纹。HTML 的指定宽度和 A4 打印由隔离浏览器实测。检查结果写入本轮事件；有可修正的失败时通过 Stop 返回原因，最多一次。复验失败或检查缺少执行条件时保留原因，收尾时不能标为成功。取消、失败、授权和实时修正以现有运行状态为准。没有命中自动检查的请求沿用原生执行语义，主观质量与未覆盖的条件仍须另行确认。

对照 Anthropic 对 outcome grader 的说明，以及锁定 SDK 的 StopHookInput、Stop hook block 决策。验证使用真实 SDK 配回环模型制造无交付、虚假完成、修复成功和重复失败，并对保留的旧产物进行真实浏览器检查。回退只移除运行结束时的验收接线，历史事件可保留。[Agent 结果评测](https://www.anthropic.com/research/demystifying-evals-for-ai-agents) · [Stop 钩子](https://code.claude.com/docs/en/hooks#stop)

实现时把可检查的交付原文限定到用户明确命名的文本原件。任务正文、输入文件中的指令、引述、条件句以及项目内保存操作不能自动成为强制交付条件。用户明确指定只回复或只交某些文件时，发布入口在写入前与登记前复核当前要求。实时插话中的明确继续、追加和替换分别绑定到对应的用户消息；已有不可变版本保留。验收事件复用原有持久化流程，聊天按消息、文件 ID 和指纹展示结果。

静态 HTML 由 Linux 隔离进程在无用户项目挂载、无网络、禁用页面脚本的环境渲染。发给模型的是失败观测和允许它采取的修正，例如实测 Letter 时指出控制实体纸张的 CSS 规则。系统缺少运行条件或文档依赖动态行为时，保留未核验结果。原版、笼统提醒、尺寸反馈与可操作反馈的实测对照见[评测记录](../task-plan-eval.md#一次修正能否改善交付)。Linux 包携带已锁定的 Playwright Core 及其许可文本；Chromium、bubblewrap、coreutils、util-linux 与 Poppler 由系统提供。

安装件验收发现两个原有缺口，源码目录上层的依赖让暂存探针能够错误通过。Linux 白名单补入定时任务所需的 Croner 和已有的 v12 至 v15 SQL。打包探针限制模块解析在暂存运行时内部，使用暂存的真实 Store 创建独立空库，逐一执行已随包交付的迁移。该改动涉及构建输入和临时测试库。

## 使用 GPT-6.1 Terra high 的运行时复测

上一轮回执显示三个可复现缺口。只读项目的模型重复寻找写入目录，未使用已有的成果发布能力。明确要求只回复计算结果的两项整数运算只核对有文字回复。Markdown 评分同时读到「待核实」和「已走验收」时会放过冲突。

- 只读运行说明明确区分项目写入和已有 `publish_artifact`。文件交付按用户要求命名并以工具回执确认，工具授权和文件存储沿用已有边界。
- 对只要求计算结果、只有一条明确二元整数算式的请求，计算安全整数并复用现有精确回复验收和一次修正。复合、歧义和不产生安全整数的算式沿用原有核对。Markdown 评分逐路径同时核对正反证据，矛盾状态记为失败。
- 旧版与修正候选输入完全相同，走各自的真实 SDK 运行入口。用现有回环 Shunt 转发用户指定的 `gpt-6.1-terra`、`high`。对照 [OpenAI 模型档位](https://developers.openai.com/api/docs/models/gpt-6.1-terra) 和 [Shunt 0.64.0 的 effort 转换](https://github.com/pleaseai/shunt/blob/ace707b/src/model/responses_request.rs#L1077)。在请求核对 `model` 和 `output_config.effort`，从流式消息核对回执模型。正式对照仅提交合成夹具，保留真实工具、验收、产物、token 和耗时。基线仍用 `1076452`，两版共用修正后的评分器。回退可恢复本轮运行说明、整数验收和评测改动。
