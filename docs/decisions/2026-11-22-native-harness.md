# 个人桌面原生执行与进展恢复

## 目标与依据

一次发行版本核验中，两个前台调查任务先后执行 58 和 20 次网页搜索。运行已得到官方链接，主会话仍在等待调查结果。本机安装状态可从包管理器读取。桌面需要同时支持本机开发、公开来源调查、文档写作及有进展的长任务。

采用仓库锁定的 `@anthropic-ai/claude-agent-sdk@0.3.326`。已核对其 `query`、原生工具清单、系统提示 preset、权限 hook 和 `stopTask` 类型。参考 [Codex 的原生循环](https://openai.com/index/unrolling-the-codex-agent-loop/)、[Agent SDK 权限评估](https://code.claude.com/docs/en/agent-sdk/permissions) 与 [任务结果评测](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。现有 `server/codex-model-catalog.ts` 用 app-server 读取模型，执行链路则已有 SDK 的原生续接、分支、回执和审批记录。继续使用该执行链路可保留用户现有的对话和操作轨迹。

## 执行契约

新建的普通 Linux 配对桌面会话选用本机执行。Shell 和文件工具具有当前登录用户的 OS 权限，项目目录作为初始工作位置。对外发送、付费服务和系统操作以用户的任务授权为准。SDK 接收运行所需的环境，配对信息归桌面框架持有。已有明确的受控模式、绑定智能体和历史队列按提交时的策略运行。运行记录保存执行器，队列、SDK 恢复指纹与关停核对其归属。启动配置 `ATELIER_NATIVE_EXECUTION=0` 可回退。

主会话从工具实际结果选择后续步骤。轻量观察器按整个运行记录进展及可复查证据，允许文件变更后重试和等待异步作业。在反馈模式下，重复的低信息结果给模型一次有针对性的提示。明确永久失败且持续停滞的子任务可停止，其他分支继续。首次交付提供观察模式和可独立切换的干预策略，效果由重复任务与正常长任务共同验收。SDK 和工具的单次失败计入同一运行，未确认副作用保留待核对状态。

并行分支共享重复结果的证据，各自记录提示投递和 90 秒冷却期。检测到停滞时记录待投递状态，构造对应分支的 SDK 工具回执时才记录提示已投递。若分支仍在自己的冷却期内，后续匹配的工具结果可以再次尝试投递。暂停判断只使用该分支实际收到提示后的重复次数。

对于同一分支反复成功的前台 Bash 命令，以完整执行参数和可比较的回执跟踪连续重复。达到既有次数与耗时条件后，工具回执会提醒模型核对是否有新信息。执行器继续把 Shell 副作用视为待核对。命令或结果变化、观测到的文件修改会重新计数。后台作业、已中断命令和截断回执按各自执行状态处理。

### 跨轮恢复

SDK 需要重建上下文时，运行时按 SQLite 的会话顺序投影之前各轮，沿用执行器与绑定智能体的恢复范围。给用户要求、来源、已完成的工具调用、待核对的副作用及未完成步骤分别分配摘要空间，保留出处和早期锚点。新一轮的用户指令放在恢复资料之后。报告完整性以各类省略计数、工具回执和原始会话记录为准。历史记录仍由 SQLite 统一持有。

### 模型接收的工具回执

运行时先保存执行器提供的回执，再决定进入模型的文本。默认阈值为 6,000 个 UTF-16 码元。Atelier 工具的长成功和失败回执使用本地摘录，命令日志选取首尾、异常行和统计，保留已有的退出状态。错误记录先脱敏。短结果直接返回。模型通过 `read_tool_output` 按已保存原文的 UTF-16 偏移读取，默认 2,000、上限 8,000，使用 `nextOffset` 续读。显式请求的页直接交付。项目模式及子任务只能读取本轮发给同一执行者的指针，本机主助手沿用同会话历史读取范围。

原生 Bash 文本、WebFetch 正文以及 Glob、Grep 的文本结果使用 `PostToolUse.updatedToolOutput` 和对应工具的原生结构。搜索的取回指针放在随回执发出的上下文中，以免把工作台说明当成搜索命中。原生 Read 采用 SDK 自身的整文件和按行范围读取契约。真实模型配对试验中，工作台把文件正文二次截为首段后，精确字段任务从 2 次模型请求增至 4 次，因此由 SDK 统一限幅并交付请求的行范围。图像、PDF、结构化 Bash 回执及有专用协议的工具走 SDK 原生路径。已保存的原文以 SDK 实际交付的范围为准，上游截断的命令输出可能另有 SDK 提供的文件位置。

原生工具执行抛错时，锁定 SDK 的 `PostToolUseFailure` 只接受 `additionalContext`。运行时保存完整的脱敏错误并附读取指针，原生非零退出 Bash 的错误正文仍由 SDK 发送。验收覆盖这一版本边界。网关代理重写会额外接管模型协议、认证和恢复，本次采用受支持的工具回调。[SDK 工具回执 Hook](https://code.claude.com/docs/en/agent-sdk/hooks)

### 记录内搜索与原生 Bash 日志

同一份构建日志的关键行在中段，按偏移翻页曾消耗两次模型往返。`read_tool_output` 支持单行字面查询，返回有界的命中片段、行号和可续读的 UTF-16 位置。搜索默认针对桌面展示的日志文本，后续传 `view: "log"` 在同一文本内读页。兼容已有读取 ID 的默认分页视图是保存的 SDK 回执。两种视图及搜索共用现有会话和执行者授权。

锁定 SDK 的成功 Bash 回执可通过 `persistedOutputPath` 提供 SDK 已落盘的日志。215,425 字节的隔离实验在这个文件内找回中段，非零退出的同题仅得到 10,040 字符错误回执。借鉴 [OpenClaw 的执行日志范围标记](https://github.com/openclaw/openclaw/blob/b8a55ae92072dac7ec0c456a04831f7284e22170/src/agents/bash-tools.exec-support.ts#L51-L55)，工作台由运行时读取经归属校验的 SDK 文本文件，随工具记录保留私有副本，每次调用的副本最多 8 MiB。展示、下载和模型检索共享保存范围。捕获失败与仅有 SDK 错误回执分别记录。原始回执保存 SDK 元数据，进程执行、退出状态和停止继续由 SDK 持有。以回环请求中的关键词命中、落盘内容和真实桌面展示验收，同时覆盖捕获失败、超限与会话清理。

## 验证及回退

在临时项目和数据根验证本机 Shell、目录外读写、子任务归属、停止和重开。使用固定网关响应覆盖确定性契约，并通过桌面输入区、执行轨迹和 SQLite 历史核对结果。自主选择的完成率和首次有用结果时长由同模型、同推理档的独立试跑评估。若命令回收、权限归属或回执验证失败，保留受控执行器并阻止该构建上线。
