# 长任务的运行上限

2026-11-20 的网页检索成功完成 16 次工具调用，SDK 用完默认 16 轮时尚未生成结论。工作台还固定了 5 分钟的运行时间和 1 美元的 SDK 估算额度。长任务需要等任务自然完成，并在工作台提供停止操作。

[Agent SDK TypeScript 参考](https://code.claude.com/docs/en/agent-sdk/typescript)与安装版本 0.3.326 的 `Options` 将 `maxTurns` 和 `maxBudgetUsd` 定义为可选值。`maxBudgetUsd` 依赖 SDK 的客户端估算。在 [openai/codex 的任务模块](https://github.com/openai/codex/blob/main/codex-rs/core/src/tasks/mod.rs)中，`start_task` 登记任务，`abort_all_tasks` 处理中断，任务生命周期按完成或取消收尾。将固定上限从 16 提到 100 仍会截断更长任务。省略 SDK 的两个可选值，并复用现有停止协议，可直接表达默认持续运行，避免新增自动续跑和工具重放。

新任务默认关闭总轮数和总时长限制。配置提供单个开关与两个可填的上限，历史默认值作为开启上限时的初值。旧配置存有自定义上限时保持启用，仍为 16 轮和 5 分钟的旧默认配置采用新的默认策略。配置继续存于原 SQLite 记录，历史 Run 保留原快照。已知计费搜索保留其单笔费用校验。手动停止、权限有效期和工具自身超时继续在原有执行端裁决。

以真实 SDK 和本地回环响应验证超过 16 次工具调用后保存最终文本，验证开启上限和主动取消。恢复旧行为可打开设置中的执行上限并填入原数值。配置字段向后兼容，旧应用仍使用原有数值字段。
