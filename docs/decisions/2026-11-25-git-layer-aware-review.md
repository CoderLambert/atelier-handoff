# Git 按层丢弃与双层差异

文件列表传入路径丢弃改动，桌面服务对跟踪文件同时恢复索引和工作区。选择未暂存行时，已纳入下次提交的内容也被删除。第二个问题是同一文件的两层差异需要重复在列表中定位。

参考 [Git restore](https://git-scm.com/docs/git-restore)、[Git clean](https://git-scm.com/docs/git-clean) 和 [dsh-plugin-git 按层丢弃](https://github.com/cherrchen/dsh-plugin-git/blob/v0.2.14/src/service.ts#L280-L339)。未暂存操作从索引恢复工作区。已暂存操作明确提示索引和工作区一起回到 HEAD。未跟踪操作仅删除选中的文件。批量操作在同一次确认中列出每个路径及影响层。

沿用逐文件暂存的项目和工作树 ID、写入互斥及受限 Git 执行器。运行时先复核所有目标，再写入字面路径。用空树作为首次提交前的恢复基线。未跟踪文件逐个删除，并复核父目录，目录和冲突留给专门的处理流程。已暂存删除的路径若出现未跟踪替代文件，拒绝恢复以保护替代内容。批量操作的后续步骤发生错误时重新读取仓库状态。Electron renderer 保留交互和确认，Git 写入由已有 Node 运行时承接，原路径式 IPC 随之清理。两层差异在现有详情区切换、按需同时查看，复用工作树、路径及层组成的查询键。两层变为一层后恢复单份差异。

先用临时仓库证明丢弃未暂存会保留索引，再覆盖按 HEAD 恢复、未跟踪文件和改名。桌面检查两种语言的预览、取消、确认与差异切换。若需撤回，移除按层丢弃入口及其路由，保留 Git 索引与文件格式。
