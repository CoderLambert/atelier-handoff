# 按原生事件顺序展示会话

用户在同一个消息页阅读模型正文、打开工具输出、处理审批，并在长时间等待时看见实际阶段和耗时。Node 运行时记录位置并保存到 SQLite，renderer 使用会话快照展示，Electron 负责窗口和现有桌面实例的切换。

原设计把所有文字存为一条消息，把工具挂在这一轮的消息上方。旧正文没有片段位置。已确认从新运行开始，旧轮次保留正文与执行轨迹入口。

## 依据和取舍

- Claude Code 2.1.332 在回环模型等待期间继续显示计时。锁定 SDK 0.3.332 实测首段正文、两个工具调用、反序返回的结果和末段正文都有独立事件。原生交互可通过详细记录查看已折叠的工具。 [CLI 交互文档](https://code.claude.com/docs/en/interactive-mode#transcript-viewer) · [SDK 流式事件](https://code.claude.com/docs/en/agent-sdk/streaming-output)
- Codex 的会话条目协议为正文和命令提供独立身份和生命周期。Atelier 采用稳定的显示位置，并复用自身的工具状态、审批和输出记录。 [Codex ThreadItem](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/typescript/v2/ThreadItem.ts)
- 仅重排当前快照的事件会受 500 条窗口及正文合并影响。为正文和工具新建整套表会重复持有已有内容。选用既有 JSON 记录上的可选元数据，由现有快照读仓储一次读取。旧版可以打开同一 SQLite schema，回退时沿用旧版的正文和工具记录读法。

## 顺序与恢复

工具位置由消费到的 SDK 内容块确定。提早到达的 Hook 先持久化执行状态和暂存位置，收到原生调用后合并到该位置。进程在两者之间中断时，恢复使用已经持久化的 Hook 观察顺序。已发出但还未执行的调用记录准备状态，停止后保留位置并显示启动前停止。未获授权的调用按实际拒绝回执展示。

每个 SDK 响应归属由已确认的用户输入标识确定。运行中插入新消息后，已在途且未带新输入标识的响应仍归原消息。正文和区间在同一短事务保存，读取使用现有快照，SSE 只通知提交后的变化。

## 实施与验收

1. 在真实 SDK 回环用例断言首段正文、并行工具的位置、原位回执和末段正文。加入至少 501 条事件再读取已重开的快照。
2. 记录 Run.transcript 的版本和通知，Message.transcriptParts 的稳定 ID、位置、UTF-16 区间和时间，用户 Message 和主线程 ToolCall 的 transcriptOrder。用 SDK 内容块位置归并完整回执与增量，按投递身份路由迟到帧。运行时同时更新正文及区间，提交后通知 SSE。
3. 消息页仅合并相邻、成功的读取类调用。已存在的工具详情、审批、子任务和重试操作归对应记录。在输入区持续展示活动状态及计时。通过 Chromium 夹具验证顺序、展开、焦点和旧轮次。
4. 在 Linux Electron 用隔离数据根和 userData 检验中英文、空窗计时、断线补齐和重开。执行完整检查、测试和构建。发布前核对当前实例空闲和同一数据根及 profile 的兼容性。回退使用上一版桌面构建。
