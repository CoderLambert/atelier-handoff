# 执行中遇到关键问题时询问

## 问题与范围

用户要求在发现缺少会改变交付的事实或决定时立即询问。已知路径且资料很少时，优先由主任务直接读取，避免仓库交接对照里的重复读取与分工。现有 Stop 验收会把等待答复当成漏交付，因此澄清必须有可核对的主运行回执。用户先交付普通聊天与执行场景。

## 查阅与取舍

[Claude Agent SDK 的用户输入](https://code.claude.com/docs/en/agent-sdk/user-input#handle-clarifying-questions) 使用 `AskUserQuestion` 和 `canUseTool` 等候宿主表单回复。该方案让同一 SDK 查询保持开启，带来新表单、答复回传和中断恢复边界。[Codex 的调查规则](https://github.com/openai/codex/blob/6bfc58a688a73c287da51797d99c3345caecbae8/codex-rs/collaboration-mode-templates/templates/plan.md#L41-L68) 先用可读证据解决已知问题，再向用户问真正依赖用户取舍的部分。沿用这个提问条件。对照现有窗口，使用现有对话回复承载问题，用户以普通消息继续。

采用已锁定 SDK 的[进程内自定义工具](https://code.claude.com/docs/en/agent-sdk/custom-tools)和工作台现有工具票据、消息及运行事件。主任务提出一个关键问题时立即写入聊天，保留原 SDK 会话供下一条消息续接。该次请求以提问收尾，同一输入结束前禁止新的工具操作，已有成果检查也阻止迟到的发布，Stop 修正与终态复验等候新输入。工具票据携带 SDK 真实提示编号，旧输入的迟到请求不得改变新输入的验收。定时任务继续走现有无人值守交付规则。未发出澄清回执的交付仍按原规则验收。实时新输入领取后继续按该输入使用现有验收规则。下一条普通聊天消息沿用会话上下文，也允许另起话题。自动验收仍按新消息明确的要求提取。分工调整只改受控执行提示，沿用已授权工具、并行调度和本机信任模式。

## 验证与回退

用锁定 SDK 的回环响应验证提出问题、即时消息、不误触交付修正、实际产物验收。隔离工作台从同一聊天回答后核对真实产物。用相同 `gpt-6.1-terra high` 和合成输入比较已知材料与缺少决定两种情况。回退该变更即可恢复原收尾和提示，已经记录的问题仍能作为普通聊天历史阅读。
