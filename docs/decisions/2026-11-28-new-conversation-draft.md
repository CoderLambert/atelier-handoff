# 首条消息提交时创建会话

连续点击工作区的「新建会话」会并发调用四次会话创建接口。隔离 Electron 中观察到 4 次 POST，即使没有输入正文。项目入口应复用同一份未发送草稿。

Open WebUI 的 [Chat.svelte](https://github.com/open-webui/open-webui/blob/main/src/lib/components/chat/Chat.svelte) 将未保存的输入留在新聊天地址，直到提交进入持久聊天。Atelier 复用现有输入区和草稿保存机制，增加按项目寻址的草稿页。草稿文字和运行偏好保存在 renderer，文件暂存在当前窗口内存，提交时走已有关联会话的上传接口。按 [HTTP 幂等语义](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)，首次提交使用固定 UUID，创建响应丢失时重试仍返回原会话。消息沿用现有幂等键。成功后只在发起草稿页仍处于当前路由时切换到正式会话。

复用并隐藏旧的空会话仍会写入 SQLite，也会增加对历史、会话级设置和工具资源的清理义务。草稿地址没有真实会话 ID，避免触发快照、终端和会话级 Skill 策略写入。已有的绑定智能体、计划任务和显式创建会话的 API 保留其生命周期。创建、上传及首发依序执行，提交失败时保留草稿供重试。跨接口失败可能发生在创建已经完成之后。

验收包括两种语言、连续点击、跨项目草稿隔离、切换与刷新、无消息时的实际会话计数、单次首发、附件和重复请求。回退可恢复原新会话导航与创建调用，无需变更 SQLite schema。
