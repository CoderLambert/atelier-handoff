# 工作台界面国际化

## 问题与范围

React 工作台、共享预览组件和 Electron 恢复弹窗的文案目前由各模块直接提供。首版覆盖应用控制的界面及其无障碍名称。简体中文 `zh-CN` 是初始语言，英文 `en` 可在设置中选择。用户内容、模型输出和原始日志作为数据展示。

## 依据与选择

- [i18next TypeScript](https://www.i18next.com/overview/typescript)、[复数规则](https://www.i18next.com/translation-function/plurals)和 [React 绑定](https://react.i18next.com/latest/usetranslation-hook)覆盖类型化词条、插值和切换订阅。依赖锁定为 i18next 27.2.4 和 react-i18next 18.0.3，后者要求 i18next >=27.0.1 并支持 React 18 及以上。构建时核对类型和许可清单。
- [Rocket.Chat Electron main](https://github.com/RocketChat/Rocket.Chat.Electron/blob/f7fb20b1f98f10a09d9df832de9737621ab16717/src/i18n/main.ts)的 `I18nService.initializeAsync()` 与 [renderer](https://github.com/RocketChat/Rocket.Chat.Electron/blob/f7fb20b1f98f10a09d9df832de9737621ab16717/src/i18n/renderer.ts)的 `setupI18n()` 各自持有实例并交换语言值。不匹配的语言回退到英文。借鉴其进程划分，Atelier 在启动工作台服务前装载 profile 偏好。
- [Joplin locale](https://github.com/laurent22/joplin/blob/9ac4aac4e51e0c788b7a2346d69fe7ff64aaaa29/packages/lib/locale.ts)的 `closestSupportedLocale()` 和 `stringByLocale()` 明确处理不支持的语言和未翻译词条。其 gettext 模式依赖源句作为键。Atelier 使用独立语义键，便于调整原句及逐步迁移界面。
- `desktop/main.mts` 在运行时启动和恢复时拥有系统弹窗。`desktop/host/runtime.mts` 的运行端口默认动态分配。Electron main 在 profile 下原子保存版本化偏好，窄 IPC 交换受控语言值。Web 使用同源存储。双语词条随包分发，缺失语言值回到 `zh-CN`，运行时缺失词条回退英文。
- [i18next CLI](https://www.i18next.com/how-to/extracting-translations)可提取和检查常见 JSX 文案。项目还要覆盖 Electron 对话框、辅助函数和既有的精确例外机制，沿用 Babel AST 检查入口，验证语义键、插值变量及各语言的复数分支。

## 验证和回退

完整检查见 `npm run check`、`npm test`、`npm run build`、`npm run build:desktop`。隔离浏览器与 Electron 验证设置切换、草稿保留、重开和启动故障，安装工件检查离线词条与许可证。偏好保存在独立文件，旧构建可继续读取相同的工作台数据目录。阶段证据见[执行日志](../../openspec/roadmaps/build-atelier-desktop/task-log.md)。
