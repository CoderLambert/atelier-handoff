# 停止反馈与 SDK 重试通知

停止只影响当前运行。回执区分正在停止和已停止，保留部分回复、工具结果和审计记录。用户明确点击「只读续接」才发起恢复运行。无需迁移旧会话或更改 Electron 主进程、IPC、SDK 版本和重试策略。

## 证据与取舍

- 事发轮次在进入 `stopping` 后才收到三条 `sdk.api_retry`。锁定 Agent SDK 0.3.332 和回环流复现了相同的 `1/10 → 1/9 → 2/9`；现有托管代理取消后，回环接收端没有收到第二次请求。外部直连对照在 429 退避期间停止，接收端约一秒后实际收到第二次请求。重试通知不是请求到达凭证，真实事发轮次没有上游完整请求日志。
- [Agent SDK 官方 TypeScript 参考](https://code.claude.com/docs/en/agent-sdk/typescript)区分取消控制器、仅流式输入支持且不自动撤销已排队输入的 `interrupt`、终结子进程的 `close`。项目锁定版本 `sdk.d.ts` 将 `api_retry` 定义为等待重试的预告。对照 `openai/codex` 的 [`codex-rs/tui/src/chatwidget.rs`](https://github.com/openai/codex/blob/main/codex-rs/tui/src/chatwidget.rs)（读取公开 main 源码），回连反馈使用暂存状态标题，发起中断时先清除活动流尾并重绘。Atelier 复用现有运行状态栏和执行轨迹，不另造通知控件，也不让 renderer 决定终态。
- 新重试通知仅记运行事件，不再生成正文行；旧序列忽略该类行但仍解析其历史格式。诊断明确是 SDK 通知，优先用停止阶段标记，旧事件按服务端序号判定；不把事件数视为已发送请求数。停止提交中只在 UI 给出临时反馈；服务端返回 `stopping` 或终态后接管。请求失败保留错误反馈并刷新真实状态。
- 外部连接单独复验：没有排队输入时，公开 `interrupt()` 再结束输入可及时断流；已有 `next/later` 输入时，429 退避和部分文本流两组各 6/6 实际发出新请求（约 15–18 ms），即使收到中断回执。提前 `close()` 还可能丢弃最终助手帧和工具回执。不启用这套不完整的取消、不依赖未公开 SDK 参数，也不全局禁重试或默认强杀。若后续确认采用外部出站闸门，应先明确认证、目标 URL、TLS、代理环境和兼容测试，且不承诺撤回已到远端的请求。隔离探针与证据位于 `.local/stop-retry-feedback/external-probe/`。

## 验证与回退

真实 SDK 回环验证正常 429 恢复、原始重试事件及停止行为；中英文隔离 Electron 操作停止和查看轨迹，核对旧回复在刷新后仍可读。前端夹具额外覆盖终态、旧通知和停止失败。保留数据库和 SDK 历史；回退撤销本轮运行事件投影、状态提示及词条，无需转换数据。已只写入事件的新重试通知仍可在旧版轨迹查看。
