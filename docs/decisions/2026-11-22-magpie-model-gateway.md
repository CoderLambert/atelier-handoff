# Magpie 模型接入

Atelier 从本机 Magpie 的 `/v1/models` 读取目录，并向原生 Agent SDK 提供该网关的 Anthropic Messages 地址。Magpie 官方说明默认回环地址为 `127.0.0.1:3425`，并在网关内处理协议转换。本机 Magpie 0.1.3194 返回 57 项模型，空的 `/v1/messages` POST 在网关入口被校验拒绝。[Magpie](https://usemagpie.ai/)

参考已有 [Shunt 模型发现](2026-11-22-model-discovery-recovery.md)。合并目录时给 Magpie 条目添加来源，并以 `magpie:` 前缀保存在会话草稿和运行记录。运行时解析前缀，去掉前缀后将原生模型 ID 交给 SDK。由此避免两个网关的 ID 冲突。配置、权限和待处理任务继续走现有运行链路。仅允许经过校验的本机网关地址，Magpie 认证独立使用运行时的 `ATELIER_MAGPIE_TOKEN`。

回环夹具覆盖读目录、暂停或失败后保留其他来源、原生请求和运行记录。真实 Magpie 以只读目录查询验收，模型生成和工具往返用回环替身验证。环境变量 `ATELIER_MAGPIE_URL` 为空时停用 Magpie 来源，默认端口为 3425。

## 独立接入开关

上一版仅凭本机端口可访问就合并目录。设置页增加「允许接入 Magpie」，复用 `AppConfig` 的 SQLite 设置记录和部分更新接口。缺少 `magpieEnabled` 的旧配置按关闭处理。用户可以单独保存该字段，保留网关与默认模型表单中的编辑。启动环境变量继续决定接入地址。

运行时读取保存后的开关，决定是否发现 Magpie 目录、接受指定 Magpie 的新运行及重试，以及是否开始投递尚未递交的排队消息。已保存的默认模型和会话选择保留，界面标明关闭状态并提示改选。关闭前已开始的运行可继续，也可用现有停止操作结束。重新开启后，已保留的选择可再次使用。回归测试覆盖默认关闭、切换、重开 SQLite、目录请求竞态、发送与重试拦截，以及 Shunt 分流。队列通过相同的运行准入检查，并在实时投递前复核开关。
