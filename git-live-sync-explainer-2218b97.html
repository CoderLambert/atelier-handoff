03

连接如何启动、恢复和退出

入口：GET /api/projects/:projectId/git/worktrees/:worktreeId/changes

  1. 1

    确定要监听哪棵树

    打开面板后默认使用所选工作树；如果正在看工作树文件，就改为监听该文件所属的树。仅对已就绪、非外部的树建立 SSE。

  2. 2

    运行时校验归属并启动双路监听

    worktrees.checkout() 解析项目根目录或属于该项目的受管工作树，跨项目 ID 返回 404。运行时读取 Git 忽略目录，启动两个 watcher；两者就绪后补发一次通知，触发对账。

  3. 3

    合并通知，也兼顾查询在途

    同一窗口内多次磁盘事件合并成一次 SSE。前端不取消正在跑的查询；若通知到来时已有读请求在途，或刷新中又收到通知，就保留待刷新标记，再补读一轮。

  4. 4

    漏报靠对账，断线靠重连

    面板挂载且页面可见时，每 15 秒校准；页面重新可见时也校准。SSE 默认建议 2 秒重连；忽略规则变化时关闭连接并建议 500 ms 重连，重新计算过滤；监听错误则建议 10 秒重连。

  5. 5

    切换或关闭面板：前端释放

    换项目、换监听工作树或卸载面板时关闭旧 EventSource，同时清理定时器和可见性监听。

  6. 6

    断连或关停：运行时释放

    HTTP 响应关闭时清理 watcher、合并计时器与心跳，并从活动流集合移除。运行时关停会结束活动流。服务端每 15 秒发一次注释心跳，它不会触发前端刷新。

04

为什么文件不串树、历史又能更新？

区分磁盘监听范围和前端查询键；共享引用可以跨树更新，但文件和暂存区不能混读。
对象如何处理
工作目录 root只观察当前连接解析出的目录。排除 .git 路径段和建立监听前由 Git 枚举到的忽略目录；不跟随符号链接。
工作树元数据 admin各工作树独立的 HEAD、index 和合并、变基等操作状态。git add 改的是所选树真实的暂存区。
仓库共享元数据 common观察 refs、packed-refs、reftable 等共享数据，不监听对象库，跳过 *.lock。同仓另一工作树提交时，共享分支引用变化也能通知主工作树的连接。
前端实时缓存 live按项目失效；文件列表、diff 和工作树文件内容的查询键进一步带工作树 ID，桌面状态键带路径。按项目触发刷新，不等于拿一棵树的结果覆盖另一棵。
提交快照缓存 OID历史分页、提交详情和提交文件内容不在 live 下。概览读到新分支尖端或当前树的新 HEAD 后，列表换到新的历史查询键；已打开的详情仍指向原提交。
例 1：终端编辑同一个文件，再执行 git add

编辑时命中工作目录监听；再次编辑即使状态仍是 M，活跃 diff 也会重读。暂存时命中所选工作树的 index 监听；重读后修改从工作区一栏移到暂存区。

例 2：受管工作树 B 提交，主工作树 A 正在看旧提交

B 的普通改动不进入 A 的文件列表；提交推进共享分支引用，A 的连接会收到通知并重新读取概览。如果 A 正在浏览该分支，历史列表会切到新尖端；已打开的旧提交详情仍显示原 SHA。
