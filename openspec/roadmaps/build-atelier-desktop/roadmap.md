# atelier 桌面版实施路线图

目标是从系统应用菜单启动可安装的 Linux x64 工作台，在同一窗口内完成项目对话、网页人工接管、受控工具执行和交付物导出，并能升级、恢复和退出。设计依据见 [整体设计](design.md)，证据与复核结论见 [执行日志](task-log.md)。

## 阶段与依赖

| 顺序 | 用户拿到的结果 | 成为实施阶段时，需要确认的依据 |
|---|---|---|
| P1 发行样包 | 从安装目录启动空白测试工作区，得到明确的网关和运行时状态 | 当前开发壳、SDK CLI 与本机 Node 版本 |
| P2 宿主与运行时 | 打开同一个应用、处理运行中退出，故障后回到项目工作区 | P1 真实进程树、数据锁、启动事件与失败日志 |
| P3 旧数据迁入 | 旧项目、历史、扩展、附件和成果在新版可查，失败可恢复 | P2 确定的写者与数据目录，历史 schema、文件清单和备份样本 |
| P4 原生浏览器 | 多标签、项目分区、地址栏、前进后退、人工接管、交还及截图在同一网页生效 | P2 生命周期和 P3 profile 决策，Wayland 下窗口缩放与弹窗样本 |
| P5 Agent 桌面执行 | 从工具发现、流式回复、审批、暂停/取消到继续及交付，在桌面跑通 | P4 浏览器 provider 合同；SkillHub、MCP、绑定智能体与网关故障样本 |
| P6 系统文件集成 | 原生选择文件/目录、粘贴/拖入、保存副本、定位成果，预览和消息可互相回溯 | P3 数据根和 P5 文件所有权、大小/格式与审批语义 |
| P7 Linux 正式发布 | 同一个实物安装包通过全功能回归、上一版升级、回退与诊断导出 | P1–P6 的发布工件、能力矩阵、数据副本和真机基线 |
| P8 Windows 移植 | Windows 安装/卸载、升级与原生输入可验收，沙箱能力有平台实现或明确不可用状态 | Linux 首发后取得 Windows 真机、签名方案、文件与命令隔离选型 |
| P9 macOS 移植 | macOS 安装、签名/公证、钥匙串权限、原生菜单和退出行为可验收 | Linux 首发后取得 macOS 构建/测试机、签名权限与平台能力评估 |

P1 → P2 → P3 → P4 → P5 → P6 → P7 是建议的单人实施顺序。P8 和 P9 均以 P7 为起点。每阶段使用 `implement-build-atelier-desktop-pN` 作为变更名，完成后再细化下一阶段。这里详写 P1、P2，因为安装件选择会直接决定进程监督和 IPC 的可行设计。P7 是 Linux 首版完成线。

## P1 · 可运行的 Linux 发行样包

**前置条件**　确认仓库规则、Electron Skill 与只读评审代理可发现，并核对阶段 0 的验证记录。在测试目录记录当前开发版能完成的桌面链路及其资源路径。确认临时数据根和 Electron `userData` 均独立。

**目标**　从 Linux x64 桌面启动安装态的应用，检验运行时、SQLite、SDK 可执行文件、PDF worker 和原生网页视图能否在发行布局下工作。（见 design.md 决策 2、5）

**子任务**　用一次变更交付发行剖面：构建可信 renderer、preload、main 和编译后的 sidecar，声明可执行资源和第三方清单，提供 package/make 与一键 smoke。实现安装目录/可写目录解析，记录外部可选能力探测。先要求本机可解包的样包，再在 P7 固化分发格式。

**验收标准**

- 在无源码、无开发用 Node/npm/tsx 的独立 Linux 用户环境启动工件。出现主窗口并能新建临时项目，重开后项目仍在。
- 禁用 Shunt 时仍能读历史并看到连接状态。使用本地模型传输替身验证打包的 SDK CLI 握手，打开一个原生网页及样例 PDF。`bwrap` 缺失时受控命令显示不可用。
- 记录系统、CPU 架构、OS 依赖、工件哈希、包体、五次冷启动的就绪耗时和退出后的进程树。记录样本规模、最慢就绪时间、峰值内存、包体和清理时限，阶段结束前冻结数值预算。失败保留命令与日志，修复后重跑同一工件流程。

**交付物**　发行样包、资源清单、可重复的打包/安装态 smoke、脱敏结果和实测门槛。旧入口作为回退路径。

## P2 · 窗口、运行时与恢复

**前置条件**　P1 的样包和启动基线可复现。用测试数据执行一次窗口关闭、子进程崩溃和重复启动，记下当前行为。

**目标**　把窗口、运行时和用户任务的生命周期明确关联。在异常退出时保护数据和待审批操作。（见 design.md 决策 1、3、4、5）

**子任务**　用一次变更交付受监督的 sidecar 和稳定宿主协议。约定启动、就绪、忙碌、退出、崩溃与恢复状态，处理二次启动聚焦、端口占用和单写者锁。收尾时先阻止新任务，再取消并等待工具/SDK/MCP，最后关闭存储。超时升级处置，记录未确认副作用。

**验收标准**

- 快速双击两次仅有一个写者且已有窗口获得焦点。其他进程占用端口时给出可恢复错误。每个 readiness 请求有超时，UI 有重新启动入口。
- 在测试任务执行中及等待审批时分别退出/强制终止。再次启动可见原会话、旧任务的中断状态和失效审批。迟到响应和旧版本客户端均不能重复执行旧动作。
- 旧宿主信道、来自外部网页的 IPC、未获配对的本地 API 调用均不能执行敏感操作，已授权入口仍可完成同一动作。
- 为 readiness、停止和恢复分别固化时间上限和超时出口，P7 以同一标准判定。连续启动/关闭十次，确认所属 sidecar、SDK/MCP 和原生网页进程完成清理。自定义目录通过路径和所有权校验，外部活跃写者保持受保护。

**交付物**　宿主与运行时契约、恢复界面、故障注入测试和打包态证据。失败时按 P1 已验证启动路径运行测试副本。

## 推进与发布

每次实施之前从设计约束派生可验证的输入、预期输出和回退步骤。状态与证据登记在 [执行日志](task-log.md)。Linux 运行样包、Linux 可发布安装包和其他平台实测各有独立里程碑。发布权限、证书、外部付费模型调用由用户在相应阶段授权。
